# kwxTypeScript

TypeScript language bindings for [wxWidgets](https://www.wxwidgets.org/) via [kwxFFI](https://github.com/KeyWorksRW/kwxFFI), enabling cross-platform GUI applications that render with native controls on Windows, macOS, and Linux.

## ⚠️ Warning: Not Production Ready

**Do not use this TypeScript/wxWidgets interface in production.**

- The kwxFFI ABI interface is **not stable** and can change without warning.
- Very little testing has been done, and won't be until late Q3 of 2026.
- API surface may change as idioms are refined.

## Requirements

- **`kwx_ts` runtime** — the self-contained TypeScript runner built from this repository. It embeds QuickJS-ng and kwxFFI and links an SWC-based TypeScript transformer, so no system Deno, Node, or npm install is required at runtime.
- **CMake 3.30+** (for building the runtime)
- **A Rust toolchain (`cargo`)** — the TypeScript transformer is compiled from source (see [Building](#building))
- A supported C/C++ compiler (MSVC, MinGW, GCC, or Clang)

## Overview

kwxTypeScript provides a two-layer binding architecture:

1. **FFI Layer** (`wx/*_gen.ts`) — Auto-generated by [kwxgen](https://github.com/KeyWorksRW/kwxgen). TypeScript classes wrapping `dlopen()` FFI symbols, with pointer operations from the `kwx/platform` module mapping directly to kwxFFI C function exports. One file per wxWidgets class.
2. **Wrapper Barrel** (`wx/kwx_gen.ts`) — Master barrel re-export of all generated bindings, constants, and the shared library handle. Users import individual classes or constants directly from here.

Users work with generated classes directly via imports. The `kwxApp` module (`src/kwxApp.ts`) provides the application lifecycle layer (initialize, main loop, shutdown).

```
TypeScript code  →  wx/*_gen.ts (FFI declarations)  →  kwxFFI (C functions)  →  wxWidgets (C++)
```

## Quick Example

```typescript
// examples/demo.ts - Hello World wxWidgets application in TypeScript

import {
  ALL, ALIGN_CENTER_VERTICAL, BOTH, DEFAULT_FRAME_STYLE,
  EVT_BUTTON, EVT_CLOSE_WINDOW, EVT_MENU, EXPAND,
  HORIZONTAL, ICON_INFORMATION, ID_ABOUT, ID_ANY, ID_EXIT,
  OK, VERTICAL,
} from "../wx/kwx_constants_gen.ts";
import { createWxBoxSizer } from "../wx/wxBoxSizer_gen.ts";
import { createWxButton } from "../wx/wxButton_gen.ts";
import { createWxClosure } from "../wx/wxClosure_gen.ts";
import { createWxFrame } from "../wx/wxFrame_gen.ts";
import { createWxMenu, createWxMenuBar } from "../wx/wxMenu_gen.ts";
import { createWxMessageDialog } from "../wx/wxMessageDialog_gen.ts";
import { createWxPanel } from "../wx/wxPanel_gen.ts";
import { createWxStaticText } from "../wx/wxStaticText_gen.ts";
import { createWxString } from "../wx/kwx_helpers_gen.ts";
import { lib } from "../wx/kwx_ffi_gen.ts";
import * as App from "../src/kwxApp.ts";
import { Callback, exit } from "kwx/platform";

// Initialize wxWidgets
if (!App.initialize()) { exit(1); }
App.setAppName("kwxTypeScript Demo");

// Create main frame
const title = createWxString("kwxTypeScript Demo");
const frame = createWxFrame(null, ID_ANY, title.ptr, -1, -1, 480, 320, DEFAULT_FRAME_STYLE)!;
title.Delete();

// Panel + sizers
const panel = createWxPanel(frame.ptr, ID_ANY, 0, 0, 0, 0, 0)!;
const sizer = createWxBoxSizer(VERTICAL)!;

const label = createWxStaticText(panel.ptr, ID_ANY,
  createWxString("Welcome to kwxTypeScript!").ptr, -1, -1, -1, -1, 0)!;
const button = createWxButton(panel.ptr, ID_ANY,
  createWxString("Click Me").ptr, -1, -1, -1, -1, 0)!;

// Connect button click event
const cb = new Callback({
  parameters: ["pointer", "pointer", "pointer"], result: "void",
}, () => {
  // ... message box logic
});
const closure = createWxClosure(cb.pointer, null)!;
lib.symbols.wxEvtHandler_Connect(button.ptr, ID_ANY, ID_ANY, EVT_BUTTON, closure.ptr);

sizer.AddWindow(label.ptr, 0, ALL, 10, null);
sizer.AddWindow(button.ptr, 0, ALL, 10, null);

frame.Show(true);
frame.Center(BOTH);
App.setTopWindow(frame.ptr);
exit(App.run());
```

A complete runnable example is in [`examples/demo.ts`](examples/demo.ts).

Run it with:

```powershell
bin\Release\kwxts.exe examples\demo.ts
```

## Module Structure

Generated TypeScript classes wrap individual C++ wxWidgets classes via FFI. Inheritance is flattened — each generated class owns its own FFI symbols for the methods it declares, and users compose inherited behavior via helper shims or direct FFI calls on the parent class's symbol set.

```
wxEvtHandler
└── wxWindow
    ├── wxTopLevelWindow
    │   ├── wxFrame
    │   └── wxDialog
    ├── wxPanel
    ├── wxButton
    ├── wxStaticText
    ├── wxTextCtrl
    ├── wxCheckBox
    ├── wxChoice
    ├── wxListBox
    └── wxComboBox

wxSizer
├── wxBoxSizer
├── wxFlexGridSizer
└── wxGridSizer
```

All objects are created through generated `createWx<ClassName>(...)` factory functions which return wrapper objects holding a `Pointer` (an opaque `void*`, typed as `bigint | null`).

## Naming Conventions

| Entity | Convention | Example |
| --- | --- | --- |
| Generated modules | `<classname>_gen.ts` | `wxframe_gen.ts`, `wxbutton_gen.ts` |
| Barrel re-export | `kwx_gen.ts` | `import { wxButton } from "./wx/kwx_gen.ts"` |
| Constructors | `createWx<ClassName>(...)` | `createWxFrame(...)`, `createWxButton(...)` |
| Methods | `PascalCase` | `.Show()`, `.Close()`, `.CreateStatusBar()` |
| Constants | `UPPER_CASE` | `EXPAND`, `DEFAULT_FRAME_STYLE`, `ID_ANY` |
| Event types | `EVT_*` | `EVT_BUTTON`, `EVT_CLOSE_WINDOW`, `EVT_MENU` |
| App lifecycle | `kwxApp.ts` | `App.initialize()`, `App.run()`, `App.exitMainLoop()` |
| Raw FFI symbols | `lib.symbols.wx*` | `lib.symbols.wxWindow_Show(...)` |

## Event Handling

Events are connected using `Callback` from `kwx/platform`, wrapped in a `wxClosure`:

```typescript
// Connect a callback to a button click
const cb = new Callback({
  parameters: ["pointer", "pointer", "pointer"],
  result: "void",
}, (closureFun, data, event) => {
  console.log("clicked");
});

const closure = createWxClosure(cb.pointer, null)!;
lib.symbols.wxEvtHandler_Connect(button.ptr, BTN_ID, BTN_ID, EVT_BUTTON, closure.ptr);

// IMPORTANT: Keep references to Callback instances alive —
// if GC'd, the native function pointer becomes dangling and causes a crash.
```

The `wxClosure` object wraps a raw `Callback.pointer` so that it can be passed through the C ABI. Event type constants (`EVT_BUTTON`, `EVT_CLOSE_WINDOW`, etc.) are plain integers exported from `kwx_constants_gen.ts`.

## Why TypeScript + wxWidgets?

TypeScript is one of the most widely adopted languages for application development, but native cross-platform GUI has traditionally required C++ or heavy framework dependencies. kwxTypeScript combines the `kwx_ts` runtime's FFI surface with wxWidgets' native rendering: one self-contained executable and a statically linked kwxFFI, with native look on every supported platform.

## Compilers & Toolchain

| Toolchain | Status |
|-----------|--------|
| MSVC `cl.exe` (Windows) | ✅ Primary |
| MinGW (Windows) | ✅ Supported |
| GCC (Linux / macOS) | 🔧 Planned |

kwxFFI and wxWidgets are built automatically from source by CMake via `FetchContent` and linked statically into the runtime.

## Building

Prerequisites:
- CMake 3.30+
- A Rust toolchain (`cargo`, from https://rustup.rs). `kwx_ts` links a TypeScript
  transformer built from source in `kwx_ts/third_party/swc_transformer`; CMake
  fetches its crates from crates.io on the first build.
- A supported C/C++ compiler (see above)
- Internet access for FetchContent (QuickJS-ng, kwxFFI, and wxWidgets are fetched automatically)

```powershell
# Configure and build (Windows, Ninja Multi-Config)
cmake --preset ninja-multi
cmake --build build --config Release --target kwx_ts
# Run the demo with the runtime built in the same configure step
bin\Release\kwxts.exe examples\demo.ts
```
